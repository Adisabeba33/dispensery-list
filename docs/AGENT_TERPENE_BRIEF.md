# ТЗ: терпены — из лабораторных анализов, а не из интернета

Проект: справочник лицензированных диспансеров NY (NYC + Вестчестер).
Репозиторий: `Adisabeba33/dispensery-list`.
Ветка для работы: `agent/terpenes-ny` (создать от `main`).

## Зачем это

Справочник кормит SŌMA — она описывает сорт по запаху и действию. Описание
держится на терпенах. Сейчас:

| | |
|---|---|
| позиций цветка | 9939 |
| **с терпенами** | **414 (4%)** |
| с лабораторным COA | **0** |
| сортов вообще без терпенов | 3500, из них **468 стоят в пяти и более магазинах** |

Четыре процента — это потолок качества SŌMA. Всё остальное она описать не
может. Причём те 414, что есть, взяты со страниц магазинов: магазин написал —
мы записали. Это лучше, чем ничего, но это не измерение.

**Задача: добыть терпены, подтверждённые лабораторией.**

## Правила доступа — не обсуждаются

robots.txt читается и соблюдается по каждому хосту. Запросы по одному, с
паузой. User-Agent честный. Капчи, логины и антибот-защиту не обходим. Простую
кнопку «мне 21» нажимаем — это уведомление, а не защита. Если ToS платформы
запрещает автоматический сбор — останавливаемся и пишем об этом в отчёт, а не
ищем обход. Меню на Leafly и Weedmaps — чужая собственность, вне работ.

## Правило, важнее всех остальных

**Пустое поле лучше правдоподобной догадки.** Не знаете — `null` и объяснение
почему. Здесь это не формальность: выдуманный терпеновый профиль звучит
убедительно, проходит любую проверку на глаз и делает SŌMA уверенно неправой.
Одно выдуманное значение обесценивает весь файл, потому что дальше никому
нельзя верить.

**Никаких «типичных профилей сорта» из головы, из общих статей, из Leafly, из
памяти модели.** Только конкретный документ, на который можно сослаться.

## Что считается основанием, а что нет

Проект различает происхождение данных, и путать уровни нельзя:

| уровень | что это | годится |
|---|---|---|
| `LAB_COA` | PDF/страница анализа конкретной партии от лаборатории или бренда, с числами | **да, это цель** |
| `MENU_LISTING` | магазин напечатал терпены на странице товара | уже собирается кодом |
| `STRAIN_REFERENCE` | усреднённый профиль сорта из нескольких COA | **да, вторая цель** |
| ничего из перечисленного | «обычно у этого сорта доминирует мирцен» | **нет** |

## Задача 1. COA-архивы брендов

Один такой архив уже найден и подтверждён — см.
`docs/TASK2_COA_RESEARCH_LOG.md`: **ElectraLeaf** публикует человеческий индекс
лабораторных анализов цветка с прямыми ссылками на PDF
(`https://electraleaf.com/3-5-flower-and-5-pack-joints-lab-test/`).
Это доказывает, что путь рабочий.

**Найдите такие же архивы у других брендов.** Начните с тех, чей товар стоит на
наибольшем числе полок — список в `enrichment-output/producer-outreach.json`
(создаётся `python scripts/producer-outreach.py`). Бренд, стоящий в сорока
магазинах, окупает час поиска; бренд из одного — нет.

Где искать: разделы сайта бренда `lab results`, `COA`, `test results`,
`certificates`, `transparency`; QR-коды и ссылки на странице товара у магазина;
страницы партий у лаборатории.

На каждый найденный архив — запись в отчёт: бренд, адрес индекса, сколько
сортов, есть ли прямые ссылки на PDF, разрешает ли robots.txt.

## Задача 2. Разбор COA в данные

Для каждого сорта из приоритетного списка (ниже) — собрать числа из COA.

Куда класть: `data/strain-reference.json`, формат уже задан схемой
`data/schema/strain-reference.schema.json`. Сейчас там 19 записей, вот такие:

```json
{
  "strainId": "blue-dream",
  "canonicalName": "Blue Dream",
  "aliases": ["Blue Dream"],
  "lineage": "UNKNOWN",
  "profile": [
    { "name": "CARYOPHYLLENE", "medianPercent": 0.2532, "observations": 3 }
  ],
  "basis": "...", "confidence": "...", "sources": [...], "lastUpdated": "..."
}
```

**Названия терпенов — строго из словаря проекта**, он в `scripts/menu-render.mjs`,
константа `TERPENES`: `MYRCENE`, `LIMONENE`, `CARYOPHYLLENE`, `PINENE_ALPHA`,
`PINENE_BETA`, `LINALOOL`, `TERPINOLENE`, `HUMULENE`, `OCIMENE`, `BISABOLOL`,
`NEROLIDOL`, `VALENCENE`, `CAMPHENE`, `EUCALYPTOL`, `GUAIOL`, `FARNESENE`,
`GERANIOL`, `BORNEOL`, `TERPINEOL`, `PHELLANDRENE`, `CARENE`, `SABINENE`,
`FENCHOL`. Чего нет в словаре — `OTHER` плюс `rawName` с исходным написанием.
Не придумывайте новых кодов.

### Правила разбора, выведенные из прошлой работы

- **`ND`, `<LOQ`, `<MRL` — это не ноль.** Не подставляйте 0. Терпен либо
  измерен, либо нет.
- **Один COA — это `confidence: LOW`.** Одна партия не описывает сорт.
- **Несколько партий — медиана, и только по измеренным значениям.** Не
  усредняйте с нулями, которых не было.
- **`observations` — сколько партий реально дали число** по этому терпену.
- Единицы: проценты массы. Если COA в мг/г — делите на 10 и пишите в отчёт,
  что пересчитывали.
- Общая сумма терпенов бывает указана отдельно — берите её как есть, а не как
  сумму своих чисел.

## Как сдавать

1. Ветка `agent/terpenes-ny`, коммиты по мере работы, не одним куском.
2. `data/strain-reference.json` — только то, что подтверждено документом.
3. `docs/TERPENE_RESEARCH_LOG.md` — журнал: что искали, что нашли, что не
   нашли и почему. **Неудачи писать обязательно**: «у бренда X анализов нет»
   экономит следующему полдня.
4. `npm run validate` должен проходить. Если валидатор ругается — не
   подгоняйте данные под него молча, напишите, в чём расхождение.
5. Pull request с описанием: сколько сортов закрыто, сколько COA прочитано,
   какие бренды публикуют анализы, а какие нет.

## Чего делать НЕ надо

- Не трогайте `data/flower-listings.json` — его переписывает ежедневный сбор,
  ваши правки затрёт.
- Не заполняйте терпены у отдельных позиций. Ваш уровень — сорт, а не витрина
  конкретного магазина.
- Не собирайте прероллы, хэш, вейпы, edibles. **Только цветок.**
- Не улучшайте код сборщика — он меняется каждый день, будет конфликт.

## Вопрос, на который нужен ответ даже без данных

Если окажется, что COA публикуют единицы брендов — **это тоже результат**, и
важный. Тогда терпены придётся брать у гроверов напрямую, и знать это лучше
через неделю, чем через месяц. Напишите об этом прямо, не пытаясь набрать
объём из слабых источников.
