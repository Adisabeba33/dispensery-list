# ТЗ агенту-исследователю: реестр лицензированных диспансеров NY (фаза 1)

**Заказчик:** проект `dispensary-list` (справочник) + `Soma` (AI-сомелье по каннабису).
**Исполнитель:** агент с доступом в интернет.
**Результат:** два JSON-файла, проходящие `npm run validate` без единой ошибки.

---

## 1. Что делаем и зачем

Мы строим публичный справочник **только легальных** диспансеров. В Нью-Йорке
работает большое количество нелицензированных точек, поэтому ценность продукта —
не в объёме списка, а в том, что **каждая запись подтверждена государственным
реестром**. Одна ложная запись обесценивает весь справочник: человек пойдёт в
нелегальную точку, думая, что она проверена нами.

Отсюда главное правило всей работы:

> **Лучше пустое поле, чем правдоподобная догадка.**
> Неизвестное значение — это `null`, а не «скорее всего да».

## 2. География фазы 1

Строго эти шесть округов, ничего сверх:

| Округ (county) | Что это |
|---|---|
| `New York` | Манхэттен |
| `Kings` | Бруклин |
| `Queens` | Куинс |
| `Bronx` | Бронкс |
| `Richmond` | Стейтен-Айленд |
| `Westchester` | округ Вестчестер (Yonkers, White Plains, New Rochelle, Mount Vernon, Peekskill и др.) |

Записи из других округов не включать даже если они попались по пути.

## 3. Источники, по убыванию авторитетности

### 3.1 Первичный — реестр лицензий штата (обязателен)

**Open Data NY, набор «Current OCM Licenses», resource id `jskf-tt3q`.**

- Страница набора: https://data.ny.gov/Economic-Development/Current-OCM-Licenses/jskf-tt3q
- SODA JSON: `https://data.ny.gov/resource/jskf-tt3q.json`
- CSV: `https://data.ny.gov/resource/jskf-tt3q.csv`
- Полная выгрузка: `https://data.ny.gov/api/views/jskf-tt3q/rows.csv?accessType=DOWNLOAD`

**Шаг 0, до всякой фильтрации:** выгрузи одну строку и запиши фактический список
колонок в `docs/SOURCE_COLUMNS.md`. Реальные имена полей (snake_case) мы не
проверяли — **не полагайся на предполагаемые имена**, сначала посмотри.

```bash
curl -s 'https://data.ny.gov/resource/jskf-tt3q.json?$limit=1' | jq 'keys'
```

Постраничная выгрузка (Socrata отдаёт максимум 1000 за раз без `$limit`):

```bash
curl -s 'https://data.ny.gov/resource/jskf-tt3q.json?$limit=50000'
```

App token не обязателен, но без него действуют жёсткие лимиты — если упрёшься в
429, зарегистрируй токен на data.ny.gov и передавай заголовком `X-App-Token`.

### 3.2 Проверка «а он вообще существует» (обязательна для статуса OPEN)

- Инструмент верификации OCM: https://cannabis.ny.gov/dispensary-location-verification
- Лицензирование OCM: https://cannabis.ny.gov/licensing

### 3.3 Данные о запрете в муниципалитетах

- OCM, локальные opt-out: https://cannabis.ny.gov/localities и https://cannabis.ny.gov/local-government
- Трекер Rockefeller Institute: https://rockinst.org/issue-areas/state-local-government/municipal-opt-out-tracker/

### 3.4 Обогащение (телефон, часы, сайт, меню) — только вторично

Сайт самого диспансера, его страница на менюшной платформе (Dutchie, I Heart
Jane, Meadow, Blaze, Treez), Google Maps.

**Weedmaps и Leafly — не источник факта лицензии.** Они перечисляют в том числе
нелицензированные точки. Их можно использовать только для часов работы и
телефона, и только после того, как лицензия подтверждена реестром.

## 4. Правила отбора записей

Включаем запись, только если выполнено **всё**:

1. Тип лицензии — розничная выдача продукта конечному покупателю:
   `ADULT_USE_RETAIL_DISPENSARY`, `CAURD`, `MICROBUSINESS` (с розничной
   активностью), `REGISTERED_ORGANIZATION_ADULT_USE`,
   `REGISTERED_ORGANIZATION_MEDICAL`.
   Культивация, переработка, дистрибуция, лаборатории, hemp — **не наше**.
2. Округ входит в список из раздела 2.
3. У записи есть номер лицензии формата `OCM-XXX-YY-NNNNNN`.

### Что обязательно исключить

- **Заявители с proximity protection.** Описание набора `jskf-tt3q` прямо
  говорит, что он содержит «all licensees **as well as applicants who have
  obtained proximity protection**». Это не лицензиаты. Их надо отфильтровать —
  определи по шагу 0, какое поле их отличает (статус лицензии / наличие номера),
  и опиши логику фильтра в `docs/SOURCE_COLUMNS.md`.
- Лицензии со статусом `REVOKED` и `SURRENDERED` — не публикуем.
  `EXPIRED` — включаем только с `operationalStatus: "PERMANENTLY_CLOSED"`.
- Cannabinoid hemp лицензии (это отдельный набор данных, не путать).

## 5. Формат выгрузки

Два файла в корне репозитория:

- `data/dispensaries.json` — массив объектов по схеме
  `data/schema/dispensary.schema.json`
- `data/municipalities.json` — массив объектов по схеме
  `data/schema/municipality.schema.json`

Схемы — это контракт, а не пожелание. Читай их целиком перед началом: там в
`description` каждого поля написано, откуда его брать. Проверка:

```bash
npm run validate
```

Скрипт проверяет не только схему, но и смысловые правила (раздел 7). Выгрузка
принимается только при нулевом количестве ошибок.

### Поля, которые надо заполнить руками, их нет в реестре

| Поле | Где брать |
|---|---|
| `geo` | геокодер. Для NYC — NYC Geoclient или Census Geocoder, оба бесплатны. Указывай честную `precision`: `ROOFTOP` только если геокодер так и сказал |
| `contact.phone` | сайт диспансера. Формат строго `+1-212-555-0100` |
| `hours` | сайт диспансера или его меню-платформа. Часы, взятые из Google Maps, помечай в `verification.notes` |
| `menu.provider` | посмотри, куда ведёт кнопка «Order online» на сайте. Это ключевое поле для интеграции с SOMA — по нему мы поймём, у скольких точек меню вообще машиночитаемо |
| `services.*` | сайт. Всё, что не подтверждено явно, — `null`, не `false` |
| `address.neighborhood` | только если уверен. Иначе `null` |

## 6. Правила верификации

`verification.status` выставляется так:

- **`VERIFIED_OFFICIAL`** — номер лицензии **и** адрес совпали с записью в
  реестре `jskf-tt3q`. Это целевое состояние для всех записей.
- **`VERIFIED_SECONDARY`** — в реестре не нашли, но два независимых
  неаффилированных источника подтверждают и лицензию, и адрес. Такие записи
  сайт покажет с предупреждением.
- **`UNVERIFIED`** — всё остальное. Сайт по умолчанию их скрывает. Если запись
  получается `UNVERIFIED`, лучше её вообще не сдавать.

`verification.confidence`:

- `HIGH` — заполнены адрес, статус, часы и контакты, расхождений между
  источниками нет.
- `MEDIUM` — основные поля есть, часть обогащения отсутствует.
- `LOW` — есть только реестровый минимум.

Каждое расхождение между источниками — строка в `warnings`, например:
`"registry address is 750 Broadway, business website says 750 Broadway Suite 2"`.

## 7. Смысловые правила, которые проверяет валидатор

Эти проверки зашиты в `scripts/validate-data.ts` — читай его, если непонятно,
чего от тебя хотят:

1. `licenseNumber` уникален по всему файлу. `id` уникален по всему файлу.
2. У каждой записи есть минимум один источник с `type: "OFFICIAL_REGISTRY"`.
3. `operationalStatus: "OPEN"` допустим только при `licenseStatus` из
   `ACTIVE` / `PROVISIONAL`.
4. `licenseStatus` из `REVOKED` / `SURRENDERED` / `EXPIRED` несовместим с
   `OPEN` и `APPROVED_NOT_OPEN`.
5. `address.borough` заполнен для пяти округов NYC и строго `null` для
   Вестчестера.
6. ZIP согласован с округом (NYC — `100xx`–`104xx`, `110xx`–`119xx`;
   Вестчестер — `105xx`–`108xx`).
7. `geo` при наличии попадает в bbox NYC + Вестчестер.
8. `verification.status: "VERIFIED_OFFICIAL"` требует источник
   `OFFICIAL_REGISTRY`.
9. Часы работы: `close` позже `open`, кроме ночных интервалов через полночь.
10. Все даты — ISO. `dates.licenseExpiration` в прошлом при `licenseStatus:
    "ACTIVE"` — это `warnings`, а не ошибка, но объясни в `verification.notes`.

## 8. Ловушки, на которых здесь легко ошибиться

1. **Активная лицензия ≠ работающий магазин.** В NY лицензии выдавали задолго до
   открытия точек. Значительная часть лицензиатов не открылась. `ACTIVE` в
   реестре при непроверенном факте работы — это `operationalStatus: "UNKNOWN"`,
   а не `OPEN`.
2. **Один оператор — несколько точек.** У The Travel Agency отдельные магазины
   на Union Square, Fifth Avenue, Downtown Brooklyn и в SoHo. Это **четыре
   записи** с разными номерами лицензий, а не одна.
3. **Адрес в реестре может быть юридическим,** а не адресом торговой точки.
   Если адрес реестра и адрес на сайте расходятся — не выбирай молча один,
   заведи `warnings` и опиши расхождение.
4. **Delivery-only лицензиаты** не имеют зала. Не выдавай их адрес за магазин:
   `services.inStorePurchase: false`, `licenseType: "DELIVERY_ONLY"`.
5. **Вестчестер: town и village — разные субъекты.** Mamaroneck существует и как
   town, и как village, и решения об opt-out у них раздельные. В
   `municipalities.json` это две записи.
6. **Около 22 муниципалитетов Вестчестера отказались от розницы** (по состоянию
   на последние публикации: Ardsley, Bronxville, Eastchester, Elmsford,
   Irvington, Larchmont, Lewisboro, Mamaroneck Town, Mamaroneck Village, Mount
   Kisco, Mount Pleasant, New Castle, North Castle, North Salem, Pelham Manor,
   Pleasantville, Port Chester, Rye City, Rye Brook, Somers, Tuckahoe,
   Yorktown). **Этот список нужно перепроверить у первоисточника** — он из
   вторичных публикаций и мог устареть. Отсутствие диспансеров в этих городах —
   норма, а не пробел в нашей работе.
7. **CAURD-лицензии переоформляются** в обычные adult-use retail. Номер при этом
   может измениться. Ориентируйся на текущее состояние реестра.
8. **Медицинские Registered Organizations** обслуживают несколько точек по одной
   организации — у каждой точки свой адрес и своя запись.

## 9. Порядок работы

1. Шаг 0: выгрузить колонки `jskf-tt3q`, записать в `docs/SOURCE_COLUMNS.md`.
2. Выгрузить набор целиком, отфильтровать по разделу 4, сохранить сырьё в
   `data/raw/ocm-licenses-YYYY-MM-DD.json` (сырьё коммитим — это доказательство
   происхождения данных).
3. Смэпить в схему. На этом этапе все поля обогащения — `null`.
4. `npm run validate` → добиться нуля ошибок ещё до обогащения.
5. Обогатить: гео, телефоны, часы, сайты, меню-платформы, услуги.
6. Проверить статус работы точек по инструменту верификации OCM, проставить
   `operationalStatus`.
7. Собрать `municipalities.json` по разделу 3.3.
8. `npm run validate` → ноль ошибок.
9. Написать `docs/RESEARCH_REPORT.md`: сколько записей всего, разбивка по
   округам и статусам, какие точки не удалось подтвердить и почему, какие
   расхождения между источниками найдены, дата выгрузки.

## 10. Критерии приёмки

- [ ] `npm run validate` — ноль ошибок
- [ ] Каждая запись имеет источник `OFFICIAL_REGISTRY`
- [ ] Доля `VERIFIED_OFFICIAL` — не ниже 95% записей
- [ ] Ни одной записи вне шести округов из раздела 2
- [ ] Сырая выгрузка сохранена в `data/raw/`
- [ ] `docs/SOURCE_COLUMNS.md` и `docs/RESEARCH_REPORT.md` заполнены
- [ ] В `RESEARCH_REPORT.md` явно перечислено, чего мы **не** знаем

## 11. Чего делать нельзя

- Придумывать номера лицензий, адреса, телефоны и часы работы. Ни при каких
  обстоятельствах, даже «для примера».
- Ставить `false` там, где значение просто не проверено. Только `null`.
- Брать факт лицензии с Weedmaps, Leafly или агрегаторов вроде
  bestdispensaries / nyscannabisguide. Только реестр штата.
- Заполнять `geo` координатами центра города, помечая их как `ROOFTOP`.
- Молча выбрасывать записи, которые не удалось подтвердить, — они идут в
  `RESEARCH_REPORT.md` с объяснением.
